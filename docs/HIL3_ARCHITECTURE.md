# HIL-3: Архитектура стенда — реальный LIS3DSH через SPI1 → SD (WeAct F405RG)

**Статус:** ✅ Собралось без ошибок и предупреждений (`pio run`), готово к прошивке.
**Цель этапа:** сквозная валидация цепочки «реальный акселерометр → 1600 Гц сбор → ping-pong буфер → VIBL-чанки на SD» — то, что HIL-2 доказал для аналогового loopback (DAC→ADC), теперь с цифровым датчиком.

---

## 1. Аппаратная часть: WeAct (SPI1 Master) ↔ Discovery (LIS3DSH)

Две платы соединены перемычками по шине SPI1. **WeAct STM32F405RG — мастер**, LIS3DSH физически распаян на плате STM32F4Discovery, но её MCU (F407) **удерживается в сбросе** и не участвует в шине.

### 1.1. Трюк NRST → GND

На Discovery перемычкой замыкают пин **NRST на GND**. Эффект:
- F407 постоянно находится в hardware reset: все его GPIO (включая PA5/PA6/PA7/PE3 — штатные SPI1 пины Discovery) находятся в высокоомном состоянии и **не конфликтуют** с шиной.
- LIS3DSH при этом продолжает питаться от VCC платы Discovery и нормально отвечает по SPI — ему не нужен F407, только SCK/MOSI/CS.
- Итог: шина SPI1 принадлежит исключительно WeAct; исключён риск bus contention (два мастера на одной шине = битые данные).

### 1.2. Карта пинов (источник: `docs/WEACT_F405_PINOUT.md` §6)

| Сигнал | Пин WeAct | Направление | Куда идёт | Примечание |
|---|---|---|---|---|
| **CS** | **PA4** | GPIO out PP, active LOW | Discovery PE3 (LIS3DSH CS) | Управляется программно (`cs_low()`/`cs_high()`) |
| **SCK** | **PA5** | AF5 SPI1 | Discovery PA5 | 5.25 МГц |
| **MISO** | **PA6** | AF5 SPI1 (вход) | Discovery PA6 | Данные датчика → MCU |
| **MOSI** | **PA7** | AF5 SPI1 | Discovery PA7 | Адреса/команды → датчик |

Дополнительно на WeAct: **PB2 = LED Blue** (Active HIGH, индикатор), **PC13 = кнопка** (см. §6), **PA8 = SD card detect** (Active LOW).

### 1.3. Конфигурация SPI1 и датчика (`lis3dsh.c`)

- Режим: **SPI Mode 3** (CPOL=1, CPHA=2EDGE) — штатный режим LIS3DSH; 8 бит, MSB-first, full-duplex.
- Частота SCK: APB2 = 84 МГц / prescaler 16 = **5.25 МГц** (в пределах спецификации датчика ~5–10 МГц).
- Инициализация (`lis3dsh_init`):
  - `WHO_AM_I (0x0F)` должен вернуть **0x3F** — иначе init падает → error loop. (0x33 — это LIS3DH, не наша микросхема.)
  - `CTRL_REG4 (0x20) = 0x6E`: ODR = 1.6 кГц + X/Y/Z enabled.
  - `CTRL_REG5 (0x24) = 0x80`: **BDU=1** — burst read: все 3 оси обновляются атомарно на одном data-ready событии → нет tearing между осями при чтении.
  - `CTRL_REG6 (0x25) = 0x03**: full scale ±16 g.

## 2. Программная архитектура: цепочка данных

```
┌──────────────┐   IRQ @1600 Гц    ┌─────────────────────────┐
│    TIM2      │ ────────────────▶ │ HAL_TIM_PeriodElapsed-  │
│ PSC=124     │   (каждые 625 мкс) │ Callback (ISR):         │
│ ARR=419     │                    │  lis3dsh_read() —       │
└──────────────┘                   │  блокирующий SPI burst │
                                    └───────────┬─────────────┘
                                              ▼ [x][y][z] int16
                                    ┌─────────────────────────┐
                                    │ Ping-Pong буфер (RAM):   │
                                    │ A: 2048 сэмплов          │
                                    │ B: 2048 сэмплов          │
                                    │ buf_ready = 1 / 2        │
                                    └───────────┬─────────────┘
                                              ▼ (только main loop)
                                    ┌─────────────────────────┐
                                    │ vibl_write_chunk()       │
                                    │ f_write(12 КБ)+f_sync    │
                                    └───────────┬─────────────┘
                                              ▼
                                    ┌─────────────────────────┐
                                    │ FatFs R0.12c → SDIO     │
                                    │ (4-bit, blocking)       │
                                    │ LOG0003.VIB             │
                                    └─────────────────────────┘
```

### 2.1. Звено 1: TIM2 @ ровно 1600 Гц

- Таймеры APB1 на F405 тактуются от **84 МГц** (APB1 = 42 МГц ×2, т.к. делитель ≠ 1).
- `PSC=124` → деление на 125; `ARR=419` → период счётчика 420 тактов.
- **84 000 000 / (125 × 420) = ровно 1600 Гц** → период сэмпла = **625 мкс**.
- Запуск: `HAL_TIM_Base_Start_IT(&htim2)` — **критично**: именно `_IT` включает update-прерывание. Без него ISR не срабатывает и сбор данных не начинается вообще (исправленный баг этой сессии).
- NVIC: `TIM2_IRQn` включён в `HAL_TIM_Base_MspInit` (`tim.c`: `HAL_NVIC_SetPriority(TIM2_IRQn, 0, 0)` + `HAL_NVIC_EnableIRQ`) — проверено.

### 2.2. Звено 2: блокирующий SPI-чтение (7 байт)

Каждый тик TIM2 вызывает `lis3dsh_read()`:
1. CS → LOW (PA4).
2. `HAL_SPI_TransmitReceive(&hspi1, tx[7], rx[7], 7, 10 мс)` — full-duplex burst:
   - байт 0 = адрес `0xA8` (`OUT_X_L | auto-increment`);
   - байты 1..6 = `[X_L, X_H, Y_L, Y_H, Z_L, Z_H]`.
3. CS → HIGH; разбор в int16 (little-endian пары).

Длительность: 7 × 8 бит / 5.25 МГц ≈ **10.7 мкс** + overhead CS/вызова ≈ **~13 мкс**. Timeout 10 мс — защита от «мёртвой» шины; нормальный burst завершается в ~13 мкс, timeout срабатывает только при реальном сбое SPI-периферии.

### 2.3. Звено 3: Ping-Pong буфер (ISR context)

- Статический массив `pingpong_buf[2048 × 2 × 3]` int16 = **24 КБ RAM**.
- Раскладка `[x][y][z]` interleave — **точно совпадает с on-disk записью VIBL** (6 байт/сэмпл) → чанки пишутся zero-copy, без конвертации.
- Семантика (та же, что в HIL-2):
  - ISR пишет `sample_idx++` по 3 halfword на тик;
  - при `sample_idx == 6144` (буфер A полон) → `buf_ready = 1`;
  - при `sample_idx == 12288` (буфер B полон) → `sample_idx = 0`, `buf_ready = 2`.
- Main loop **только** читает флаги и коммитит готовую половину; ISR никогда не трогает FatFs.

### 2.4. Звено 4: main loop → `vibl_write_chunk`

- При `buf_ready == 1`: запись `pingpong_buf[0]` (2048 сэмплов); при `== 2`: запись второй половины.
- Один чанк = `[chunk_hdr 6 B][2048 × 6 B]` ≈ **12 КБ**; внутри: `f_write` + CRC32 + `f_sync` (power-loss safety) + корм IWDG.
- FatFs R0.12c **не ISR-safe** → все файловые операции строго в main loop.

## 3. Бюджет времени: почему сэмплы не теряются

| Параметр | Значение | Расчёт |
|---|---|---|
| Период TIM2 (бюджет на один сэмпл) | **625 мкс** | 84 МГц / (125 × 420) = 1600 Гц |
| Чтение одного сэмпла по SPI | **~13 мкс** | 7 байт × 8 бит @ 5.25 МГц + overhead |
| Загрузка ISR | **~2%** (13/625) | запас > 98% — даже при джиттере SPI срыв невозможен |
| Время заполнения половины буфера | **640 мс** | 2048 × 625 мкс |
| Худший кейс коммита чанка (f_write + f_sync) | **≤ ~250 мс** | измерено в HIL-1/HIL-2; < 640 мс → steady-state без переполнения |

Вывод: чтение занимает ~2% периода таймера, коммит SD — ≤ ~40% окна между READY-флагами. Ни одно звено не блокирует следующее: **потеря сэмплов исключена по построению** (в отличие от HIL-1, где фиктивные данные не нагружали SPI).

## 4. Защита от сбоев

### 4.1. `hil3_error_loop`

Любой сбой на старте или в работе переводит систему в детерминированное состояние:
- **Точки входа:** `lis3dsh_init() != 0`, `f_mount != FR_OK`, `vibl_open != VIBL_OK`, `lis3dsh_err` (latch из ISR при неудачном SPI-read), `vibl_write_chunk != VIBL_OK`.
- **Поведование:** бесконечный цикл — мигание синего LED PB2 каждые 100 мс + `HAL_IWDG_Refresh`. Оператор видит: «система жива, но в ошибке».

### 4.2. IWDG (independent watchdog)

- Конфигурация (`iwdg.c`): prescaler **8**, reload **4095**, LSI ~32 кГц → таймаут ≈ **1–1.5 с**.
- Кормится в трёх местах: main loop (каждый оборот), внутри `vibl_write_chunk()`/`vibl_open()`/`vibl_close()` (SD-операции могут занять до ~200 мс — корм гарантированно успевает), и в error loop.
- Роль: если FatFs/SDIO зависнут намертво (не вернутся из блокирующего вызова) или ISR перестанет кормить цикл — IWDG делает hardware reset за < 1.5 с. Это **последний рубеж** после SPI-timeout (10 мс).

### 4.3. Иерархия защиты (от быстрого к медленному)

| Уровень | Механизм | Время реакции |
|---|---|---|
| 1 | SPI timeout в `lis3dsh_read` | 10 мкс → 10 мс |
| 2 | Latch `lis3dsh_err` → error loop | следующий оборот main loop |
| 3 | IWDG reset | ≤ 1.5 с |

## 6. Безопасное завершение сессии (кнопка PC13) — черновик HIL-4

Схема WeAct (`docs/WEACT_F405_PINOUT.md` §2): кнопка на **PC13** замыкается на **VDD33 через 330 Ом**, т.е. **Active HIGH**; внешнего подтягивающего резистора на GND нет → при инициализации **обязательна внутренняя подтяжка вниз**. В `gpio.c` уже настроено: `PC13 = GPIO_MODE_IT_RISING + GPIO_PULLDOWN`. Нажатие детектируется по `GPIO_PIN_SET`.

Логика (черновой код закомментирован в `main_hil3.c`, чтобы не сломать текущую сборку):
1. **Антидребезг:** polling-окно 20 мс (4 × 5 мс); нажатие засчитывается, только если пин держится HIGH всё окно.
2. **Последовательность shutdown** (весь код — в main loop, FatFs не ISR-safe):
   - `HAL_TIM_Base_Stop_IT(&htim2)` — остановить сбор;
   - `vibl_close()` — финализировать header (`record_count` + CRC) и дописать trailer;
   - `f_mount(NULL, "0:", 0)` — размонтировать SD (flush FAT-таблиц).
3. **Safe-Off:** бесконечный цикл: мигание синего LED PB2 раз в секунду (500 мкс on / 500 мкс off) + `HAL_IWDG_Refresh` — сигнал оператору «данные на диске, питание можно отключать».

## 7. План верификации HIL-3 на стенде

1. Прошить (`pio run -t upload`, ST-Link), вставить SD-карту (PA8 → LOW).
2. Включить: LED PB2 должен **не мигать** (нормальная работа) — мигание = error loop.
3. Через 30–60 с отключить питание, вытащить карту.
4. Проверить `LOG0003.VIB` парсером (`parser_vibl.py`): header CRC, sensor="LIS3DSH", sample_rate=1600, отсутствие seq-jumps; на X/Y/Z — реальный спектр вибрации (а не синус 10 Гц из HIL-2).
