# HIL-2: ПОБЕДА — Сквозная запись реального аналогового сигнала @1600 Гц (DAC→ADC loopback)

**Статус:** ✅ Успешно. Записан и верифицирован файл с **31 чанком / 63 488 сэмплов, 0 пропусков**.
Python-парсер прочитал все данные даже из оборванного файла (без трейлера — питание было отключено).

---

## 1. Архитектура теста

Цель HIL-2: проверить **всю** цепочку «аналоговый вход → непрерывный сбор @1600 Гц → буферизация → SD → ПК» до приезда LIS3DSH, заменив датчик аппаратным loopback.

```
┌─────────┐   TRGO    ┌──────────────┐  DMA (circular)   ┌─────┐
│  TIM2   │──────────▶│ DAC CH2 PA5  │──────────────────▶│     │
│ @1600 Гц│           │ синус-таблица│                   │перемычки:
│ PSC=124 │           └──────────────┘                   │ PA5→PA0 (X)
│ ARR=419 │   TRGO    ┌──────────────┐  DMA ping-pong    │ PA5→PA1 (Y)
│         │──────────▶│ ADC1, 3 chan │◀───────────────── │ PA2 (Z) — floating
└─────────┘           │ PA0/PA1/PA2  │                   └─────┘
                      │ 12-bit       │
                      └──────┬──────┘
                             ▼ half-complete / full-complete callbacks
                      ┌──────────────┐   chunking (2048 samp/chunk)   ┌─────────────┐
                      │ ring buffer  │──────────────────────────────▶│ FatFs R0.12c│
                      └──────────────┘                                │ SDIO blocking│→ MicroSD (.VIB)
                                                                     └─────────────┘
```

### Параметры каждого звена (все числа обоснованы)

| Звено | Конфигурация | Расчёт / обоснование |
|---|---|---|
| **TIM2** | PSC=124, ARR=419, прерывание включено | Таймер APB1 на F405: 84 МГц (APB1=42 МГц ×2 при делителе ≠1). 84 000 000 / 125 / 420 = **ровно 1600 Гц**, период сэмпла = **625 µs** |
| **DAC CH2 (PA5)** | DMA circular, триггер TIM2 TRGO | Таблица синусоиды в RAM; один отсчёт LUT на тик → частота тона = 1600 / период_LUT. Период LUT = 160 сэмплов → **тон ровно 10 Гц** (1600/160) |
| **Перемычки** | PA5→PA0, PA5→PA1; **PA2 намеренно не подключён** | X и Y получают идентичный сигнал; Z — управляемый «floating» для проверки поведения неподключённого входа (см. §3) |
| **ADC1** | 3 канала (PA0/PA1/PA2), 12 бит, DMA ping-pong, триггер TIM2 | Два буфера: half-complete callback копирует заполнившийся буфер в ring buffer, пока DMA пишет во второй → **нулевая потеря сэмплов при чтении** (критическое отличие от HIL-1) |
| **Ring buffer → VIBL** | чанки по 2048 сэмплов | Формат тот же, что в HIL-1: 3 оси × int16 = 6 байт/сэмпл + заголовок чанка. Чанк = 2048 × 6 ≈ 12.3 КБ данных; время чанка = 2048 / 1600 = **1.28 с** |
| **SDIO / FatFs** | блокирующий режим, FatFs R0.12c, детект карты PA8 (Active LOW) | Без изменений от HIL-1 — слой хранилища уже верифицирован (CRC header + CRC32 файла) |
| **IWDG** | таймаут ~1.5 с | Кормится в цикле записи; защита от зависания при SD-операциях |

Ключевая архитектурная идея: **сбор и запись полностью асинхронны**. DMA ADC работает непрерывно (ping-pong), CPU лишь копиит буферы в ring buffer и пишет чанки на SD. Ни одно звено не блокирует следующее — поэтому пропусков быть не может по построению, а HIL-2 это подтвердил экспериментально.

## 2. Доказательства успеха

| Метрика | Значение | Как проверено |
|---|---|---|
| Чанков записано | **31** | Python-парсер: 31 валидный чанк с корректными заголовками |
| Сэмплов | **63 488** (= 31 × 2048) | Подсчёт парсером; арифметически ровно 31 полный чанк — без обрезки внутри чанка |
| Длительность записи | **39.68 с** (63 488 × 625 µs) | ≈ 40 с непрерывной работы @1600 Гц |
| Пропуски (Gaps) | **No — 0** | Парсер сверил последовательность индексов сэмплов: разрывов нет |
| Ось X, ось Y | **идеальная синусоида 10 Гц** | Визуальный/спектральный анализ распарсенных данных; период = 160 сэмплов — ровно как задано в LUT DAC |
| Ось Z | шум (noise floor) | Ожидаемо: вход PA2 не подключён (floating pin), см. §3 |
| Целостность при обрыве питания | **все данные прочитаны** | Файл оборван без финального трейлера (питание отключили в процессе записи); парсер восстановил все 31 чанк целиком |

### Два структурных вывода из результатов

1. **Формат VIBL устойчив к обрыву питания.** Каждый чанк самодостаточен (свой заголовок/CRC), поэтому отсутствие финального трейлера не делает данные нечитаемыми. Это прямое следствие chunked-дизайна: потеряно максимум один незаписанный чанк (~12 КБ, 1.28 с данных), а не весь файл.
2. **Цепочка «сигнал → SD» прозрачна.** Синусоида на X/Y пришла в файл без искажений, смещений фазы и потери амплитуды: ни буферизация, ни DMA, ни FatFs сигнал не фильтруют и не ломают. Система передаёт то, что лежит на пинах, — 1-в-1.

## 3. Урок про floating ADC (шум на неподключённом пине)

**Наблюдение:** ось Z (PA2) содержит шум, хотя «датчика» там нет.

**Физика:** невыведенный вход АЦП — это высокоомная цепь с паразитной ёмкостью; он подхватывает наводки от соседних пинов (в первую очередь — от PA0/PA1, несущих тот же синус), переключений и питания. Результат — не «нуль», а шумовой фон.

**Практические выводы:**
- **Шум на Z — это не баг системы, а эталон noise floor.** Он показывает реальный уровень шума ADC+ввода: в production этот же уровень будет фоновым под сигналом LIS3DSH и задаёт нижнюю границу чувствительности.
- **Правило для HIL-тестов:** неиспользуемые каналы АЦП либо замыкать на GND (детерминированный ноль), либо сознательно оставлять floating как референс шума. Никогда не интерпретировать «шум на пустом канале» как сбой датчика или DMA.
- **Для production урок снимается сам собой:** LIS3DSH — цифровой SPI-датчик, все три оси приходят по MISO; аналоговых floating-входов в схеме не остаётся.

## 4. Вывод: система готова к реальному датчику LIS3DSH

**Что доказано HIL-2 (и что теперь можно считать «побеждённым»):**
- Непрерывный сбор @1600 Гц без пропусков под реальной нагрузкой записи на SD (40 с, 0 gaps).
- DMA ping-pong ADC: копирование буферов не блокирует acquisition.
- Слой хранилища (FatFs + SDIO blocking) выдерживает длительную запись; формат VIBL переживает обрыв питания.
- Python-парсер надёжен как инструмент верификации для всех следующих этапов.

**План миграции на LIS3DSH (по `docs/WEACT_F405_PINOUT.md`):**

| Шаг | Действие | Источник |
|---|---|---|
| 1 | Включить SPI1: SCK=PA5, MISO=PA6, MOSI=PA7, CS=PA4 (программно управляемый) | pinout §6 |
| 2 | **Отключить DAC** в production-прошивке | см. WARN ниже |
| 3 | Инициализация LIS3DSH: сброс (0x25→0x80), ODR=1600 Гц, BDU=1, XYZ=1 (0x20→0xBF), масштаб ±16g (0x24→0x20) | практика из reference_vibro_architecture.md / истории дня 2 |
| 4 | Сборка по DRDY-gated схеме (TIM2 как polling-часы, SPI RX DMA ≤4 байта/сэмпл → SPSC ring buffer) — acquisition больше не зависит от ADC/DAC | reference_vibro_architecture.md §3.2 |
| 5 | FatFs, VIBL-чанки, SDIO, IWDG, парсер — **без изменений** (доказаны HIL-1/HIL-2) | этот документ + HIL1_SUCCESS.md |

> ⚠️ **WARN (конфликт пинов):** pinout §5 предлагает «DAC перенести на PA4 (DAC_CH1)», но в том же документе §6 назначает **PA4 = LIS3DSH_CS**. Эти два назначения конфликтуют. Решение: в production **DAC отключается полностью** (он нужен только для HIL-тестов); если DAC захотят оставить для будущих loopback-тестов — CS датчика перенести на другой свободный GPIO.

**Итог:** вся «медная» часть системы (сбор → буферы → SD → ПК) верифицирована сквозным тестом с реальным аналоговым сигналом. Остается заменить источник сигнала: ADC/DAC loopback → SPI1 + LIS3DSH. Архитектура downstream от ring buffer не трогается.
